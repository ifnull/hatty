# Phase 5, round two — visual direction

Round one got the data right and the look wrong. This round changes the visual language,
not the data selection.

Generated by [`render_v2.py`](render_v2.py), which — like round one — asserts every line is
exactly 100 columns.

---

## First: can we use sampler's code?

[sqshq/sampler](https://github.com/sqshq/sampler) (14.8k stars) is the right reference to
have reached for. Two answers, and the first one is a hard no.

**Its code cannot be used. It is GPL-3.0.** Copying any meaningful part would compel hatty
to be GPL-3.0 as well. That forecloses the permissive open-source option in decision D2, and
it is not a decision to make accidentally by lifting a widget.

**And it would not fit anyway.** Sampler is built on `gizak/termui/v3` → `nsf/termbox-go`.
Termui is *imperative*: widgets draw into a cell buffer and own the screen. Bubble Tea
(decision D29) is the opposite — `View()` returns a **string**, composed with Lip Gloss.
A termui widget cannot be placed inside a Bubble Tea view. These are different rendering
paradigms, not different APIs.

**What can be taken is the visual language, which is what actually matters here.** Layouts,
proportions and the idea of a runchart with a cur/min/max/avg legend are not copyrightable.

### The library that does fit

[NimbleMarkets/ntcharts](https://github.com/NimbleMarkets/ntcharts) — **MIT licensed**,
purpose-built for Bubble Tea and Lip Gloss. Charts do *not* implement `tea.Model`; they
render to strings for composition inside a larger `View()`, which is exactly the shape hatty
needs. It provides line charts (time series, waveline, streamline, scatter), sparklines,
bar charts and heatmaps, with **Braille rendering** on the time-series and streamline types.

Most valuable of all: it exposes a **Canvas** — a 2D grid of arbitrary runes with Lip Gloss
styling. That is a direct fit for the polar radar scope, which no charting library provides
off the shelf.

**Recommendation: adopt ntcharts, study sampler, copy neither line of its code.**

## What was actually wrong with round one

Not the data. The **hierarchy**. Every element had the same visual weight: label on the left,
value on the right, a small bar underneath, repeated thirty times. It read like a
spreadsheet.

Sampler and btop use **scale** to create hierarchy — a big number for the thing that matters,
charts that fill their panel rather than a 30-character sparkline, and far fewer, larger
elements. Round one had none of that, and no amount of rearranging the same widgets fixes it.

Three primitives were missing, and are added here:

- a **Braille canvas** (2×4 sub-cell), which is what makes curves look like curves
- a **block-digit font** for hero numbers
- **runcharts with legends**, sampler-style

> **Braille is assumed below.** Spike S2 has not run. If it fails, these degrade to the
> block-element versions in round one — which is why round one was drawn first.

## Recommendation

**Direction 3 as the primary `radar` screen, with Direction 1's runchart treatment applied to
`home`.**

Direction 3 balances the two things that matter — spatial awareness from the scope, and the
table that carries the detail — while Direction 1 proved that a full-width runchart with a
statistics legend is worth more than four sparklines. The `home` screen is trend-heavy and
sparse, which is exactly what Direction 1's language is for.

Direction 2 is worth keeping as a **full-screen scope mode** — a keypress that expands the
scope to the whole grid. It costs almost nothing once the Canvas exists, and it is the view
you would want when something interesting is overhead.

## Still open

- **Colour.** Everything above is monochrome. Colour semantics is the next pass, and it is
  where state communication actually happens (altitude bands, alert severity, receiver health).
- **Alert treatment.** `binary_sensor.airspace_alert_military_close` firing should be
  impossible to miss. None of these show it.
- **Responsive behaviour** below 100×30 (decision D26).
- **Spike S2**, which decides whether any of this Braille survives on the panel.
